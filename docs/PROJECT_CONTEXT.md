# AquaMap Laguna

A Laravel + MySQL GIS information system focused on 53 supported profiles (11 lakes, 29 rivers, 13 waterfalls), with two hidden legacy Spring/Resort records stored pending separate deletion approval (55 total). Administrator Manage Reports retains Send to Municipality with duplicate-safe confirmation and a separate reason-required Reject Report action for safely unforwarded reports. Successful SMTP acceptance places reports in Forwarded / Processed Reports; administrators then record Under Review, In Progress, documented Resolved or separate reason-required Closed. Email delivery never changes resolution automatically. New resolutions require remarks plus a documented basis/supporting evidence reference; existing history/photos remain intact. One recipient per exact verified municipality covers multiple bodies; ambiguous boundaries require manual selection. All seven provisional entries remain at aquamaplaguna@gmail.com. SMTP acceptance is recorded for a new user-initiated referral and an explicitly reapproved old report. The user confirmed Gmail receipt in chat; the old report also has a separate in-app receiver-confirmation audit. The correct worker runs on municipality-referrals; five old referrals jobs remain preserved/paused. Patola, Alpine.js and deployment remain outside scope.

The public dashboard opens directly to a left search/category/list sidebar and right Leaflet map, split 25%/75% at desktop widths of at least 1100 px. Tablet keeps its existing columns; mobile provides a collapsible complete sidebar. Selecting a marker, shape or list item clones its inert profile template into one nonmodal profile with four bottom sections, including Research & Sources. The public all-profile reference library is removed; underlying research remains intact. Source/calculated measurements remain separate. Focus/click enables deliberate wheel/trackpad zoom. One fixed Report a Concern link leads to the public reporting form. The additive Tadlac import requires no migration.

ResearchSources consolidates each document once per profile across six evidence groups, retaining claims, source dates/revisions, page/table links and licensing. Unknown metadata remains explicit; link reachability is recorded separately from evidence validity. The earlier 54-profile baseline and 248 URLs were audited; see RESEARCH_AUDIT.md and its machine-readable ledger. No runtime network checks or stored-data changes are introduced.

Public research distinguishes historical fish occurrence from unassessed suitability. Report locations, contacts, private photos, reviews and referral history remain administrator-only. Precise coordinates and approved photo attachments may be shared only through an explicitly reviewed private referral; reporter name/email and public evidence URLs are excluded. GPS is requested by user action, shown with device accuracy, and requires explicit confirmation as the problem point; manual selection remains available. New reports retain required private photo proof and existing anti-spam protections. No scientific pollution percentage or suitability engine exists.

Use **Pagsanjan Falls** (existing ID 6) and **Taytay Falls** (existing ID 20) as primary names everywhere. Cavinti Falls/Magdapio Falls and Majayjay Falls remain alternative names in Research & Sources and searchable aliases. Never create separate records or change their existing geographic, photo, fish or report associations for a display-name correction.

`WaterBody::CATEGORIES`, PUBLIC_CATEGORIES and REPORT_CATEGORIES support only Lakes, Rivers and Waterfalls. The shared supported query also excludes resort site metadata and non-null legacy spring subtypes. New model records and shared catalogue imports reject unsupported entries; new reports require a supported existing body. Historical reports remain readable privately. Public coverage is 26 photographs and 27 placeholders; archived image/source metadata and assets remain intact. Nine optimized Google Doc photographs retain the owner-confirmed permission, credits and unidentified-author qualifications. See IMAGE_INVENTORY.md.

Run `php artisan waterfalls:import --no-interaction` for only the two reviewed missing falls; it never runs migrations or overwrites existing metadata and refuses unexpected databases/alias conflicts. Full ExplorerSeeder fixture imports include the additive waterfall catalogue. Source points retain explicit photo/community-reference accuracy limits; no new fish records, environmental measurements or pollution reports were created.

Run `php artisan lakes:import --no-interaction` explicitly for the reviewed Tadlac addition. It reuses guarded transactional identity/metadata checks, rejects alias conflicts and preserves repeat-import timestamps. ExplorerSeeder's original baseline remains unchanged. Source evidence and the withheld Patola candidate are documented in RESEARCH_SOURCES.md.

All report data and counters stay administrator-only; the redesigned public map has no aggregate exception.

Recent same-session lake/type repeats receive a nonblocking warning after saving privately as pending; other people's report history is never queried for warnings.

Row-locked reasons, follow-up and resolution notes append to existing audit history without schema changes; unsent cancellation blocks later delivery/retry. Manual/drag/GPS-confirmed pins and all reporting safeguards remain. User-initiated SMTP acceptance and user-confirmed Gmail receipt are verified separately from Mail::fake() tests; see EMAIL_REFERRALS.md. Further deployment, measurement ingestion and suitability work remain unapproved.

# AquaMap Laguna

A Laravel + MySQL GIS information system for a six-day school mini hackathon. The initial three-lake dataset is now supplemented by a sourced, eleven-profile GIS subset spanning lakes, river reaches, waterfalls and one spring-associated resort in Laguna.

- **Implemented Day 1:** schema/model alignment, sourced geographic seed data, safe repeatable seeding, isolated tests, and project documentation.
- **Implemented Day 2:** public Blade/Tailwind lake explorer at `/map`, database-driven Leaflet markers, OpenStreetMap basemap, responsive selection/details, public-field filtering, and desktop/mobile browser checks. `/` redirects to the explorer.
- **Implemented Day 3:** sourced historical Nile tilapia aquaculture records for the three lakes, general FAO habitat information, nullable study metadata, idempotent fish seeding, and responsive fish cards integrated with map selection. Occurrence is separate from unassessed compatibility.
- **Implemented Day 4:** public reporting form at `/reports/create`, validated/throttled submissions at `POST /reports`, server-assigned pending status, optional explicit incident points, private photos/contact details and generic confirmation. Reports are not publicly readable. Existing schema and research data are unchanged.
- **Constraints:** modify only this project; persistent database work is restricted to `aquamap_laguna`. Never reset databases, expose/change credentials, or fabricate measurements, pollution reports, or habitat conclusions.
- **Implemented Day 5:** administrator-only session login, protected dashboard/counts, report search/filters/pagination/details, private evidence streaming, controlled status transitions and atomic audit history. New admin accounts require the interactive local `admin:create` command; no public registration or community accounts exist. Individual reports stay private; the requested GIS expansion publishes only per-water-body aggregate counts of currently verified reports.
- **Implemented local anti-spam:** anonymous reports now have a hidden honeypot and an encrypted, session-bound 3-second server timer (2-hour validity). The existing 5-attempts/hour/IP limiter remains unchanged. Recent same-session lake/type repeats receive a nonblocking warning after saving privately as pending; other people's report history is never queried for warnings.
- **Implemented GIS expansion:** category/search/count filters, source-checked points/polygons/river reaches, responsive evidence profiles, controlled photo handling, verified-report aggregates, idempotent import and regression checks. The full requested catalogue and most resort verification remain outstanding; see research inventory.
- **Planned Day 6:** confirm the final integration/demo brief and deployment/recovery requirements. No measurement ingestion, automatic notifications or suitability engine exists. Original journal-point datum and positional precision remain unverified and visibly qualified; the expansion maps separate source-checked WGS84 geometry, without claiming survey accuracy. See [RETENTION_POLICY.md](RETENTION_POLICY.md) for the prototype's manual privacy/retention process; no automatic deletion is implemented.

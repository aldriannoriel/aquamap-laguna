Updated 2026-10-17 for the verified-first GIS expansion from `0c55ea9`. Existing Days 1-5 and anti-spam boundaries are preserved.

## System and request flow (Observed)

- PHP 8.4, Laravel 13.37, MySQL; Composer manifest/lock define backend dependencies. Laravel Boost is a development dependency installed as required by the original `AGENTS.md`; it generated agent guidelines, skills and MCP configuration.
- `public/index.php` enters `bootstrap/app.php`. `routes/web.php` redirects `/` to `GET /map`, handled by `MapController@index`. Public `GET /reports/create` and throttled `POST /reports` use `PollutionReportController@create/store`. The `/admin` group adds administrator session login and protected dashboard/report/review/photo routes. Laravel's `/up` health route remains configured in `bootstrap/app.php`. There is no public report listing/detail/download API or registration.
- `config/database.php` defines connections; the current default and connected schema were verified as `aquamap_laguna` on MySQL without recording credentials. Session and infrastructure tables exist. There are no queued domain jobs, domain events, or scheduled domain tasks.

## Community reporting flow (Observed)

The shared `resources/views/partials/header.blade.php` and a map-page link lead to the reporting form. `PollutionReportController@create` selects IDs/names/geography from existing `WaterBody` records and projects only IDs/names and a verified geometry vertex for orientation; it never loads reports. `resources/views/reports/create.blade.php` uses the existing environmental theme, labeled fields, accessible error summaries, mobile stacking and no-store responses.

`StorePollutionReportRequest` validates an existing lake, a predefined observation type (`PollutionReport::TYPES`), description up to 5,000 characters, optional bounded coordinate pair, optional name/email and optional JPEG/PNG/WebP up to 5,120 KiB. Upload content and filename extension are checked. Standard web middleware provides CSRF/origin protection. `AppServiceProvider` defines the named IP limiter: five POST attempts per hour, including invalid submissions, with a friendly 429 and retry headers. Users sharing an internet address share the limit.

The public controller explicitly assigns validated attributes to the guarded model and always sets `status = pending`; client status/path/ID/timestamps are ignored. Photos receive generated names on the dedicated `pollution-reports` disk, rooted outside `public`, with private visibility and no filesystem-serving route. Contact attributes and photo paths are also hidden from model serialization. Day 5 report reading and evidence streaming require administrator authorization; no public report read/download routes exist. Hidden attributes are defense in depth, not authorization.

A failed database save attempts to delete its newly stored photo and returns a generic error. Cleanup/storage failures log only generic context and exception class, without request contents or SQL bindings. If storage is unavailable, orphan cleanup can require operator intervention. Only scalar form fields are flashed on validation/save failure; Blade escapes them. Photos must be reselected. Success redirects to a generic pending confirmation without report IDs, contents, paths or contact details.

### Free local anti-spam protection (Observed)

`resources/views/reports/create.blade.php` includes a `website` honeypot inside a hidden/aria-hidden container, excluded from tab order and autocomplete. `StorePollutionReportRequest` accepts only an absent/blank field and rejects nonempty or malformed values before any photo/report persistence. The field is not repopulated or logged. Existing server validation, CSRF/origin protection and five POST attempts/hour/IP are unchanged; rejected attempts still consume that existing quota.

`app/Rules/ReportFormToken.php` issues a Laravel-authenticated encrypted token containing a purpose tag, server millisecond timestamp and a hash of the current session's CSRF secret. No key/configuration is changed. The server requires at least 3,000 ms since issuance, rejects future/corrupt/missing/cross-session tokens and expires them after two hours. Client-supplied timestamps cannot override it. Valid tokens retain their original age across validation retries; expired/invalid ones are replaced on the redirected form while safe text/point inputs remain available. No JavaScript, external API or citizen account is required. Tokens are reusable during their validity, not single-use or proof of a human.

After successful validation the public controller loads only the current anonymous session's last ten receipt IDs, constrained to actual submissions within one hour. The query selects only IDs/lake IDs/types and orders by ID. Matching lake and type sets a boolean warning; different descriptions can still be legitimate. The new report is always saved as pending, then a private confirmation explains a possible repeat without blocking, linking to prior reports or exposing their contents/contacts/IDs. Only successful report IDs enter the bounded session list; obsolete/missing IDs are pruned on the next successful submission. Request parameters cannot supply this history. There is no global lookup or new identity/IP fingerprint for duplicate detection.

These checks reduce basic bots but cannot identify determined bots or manual trolling: bots can avoid the honeypot, obtain a valid token and wait. Session resets/browsers can bypass the repeat hint, and simultaneous requests can miss a hint. Shared browser sessions share their hints; shared IPs retain the existing shared quota. Administrator verification remains necessary. No dependency, schema, seeder, account, credential or scientific-data change was needed. Receipt retention follows `docs/RETENTION_POLICY.md`.

`resources/js/incident-map.js` initializes a separate conditional Leaflet map using database reference points. Lake selection centers the map without assigning or changing incident coordinates. Explicit map clicks/taps or the keyboard-accessible map-center button select an orange incident point; blue circles remain lake references. Clearing, optional omission and restoration after validation work independently. No device geolocation or incident accuracy claim is made. Coordinate datum/precision caveats remain visible on both maps; community observations do not become scientific measurements, suitability conclusions or confirmed pollution findings.

Day 4 needed no migration/dependency; Day 5 added the administrator flag and audit table. The GIS expansion adds eight water-body metadata columns and a separate explicit seeder; existing attributes/relationships remain intact. `scripts/serve-local.ps1` starts a local-only PHP server with process-local 5 MB upload / 8 MB POST limits; the machine's default PHP upload limit is 2 MB. Other servers must configure equivalent limits. Credentials/global PHP settings are untouched.

## Administrator review flow (Observed)

Access has two levels: anonymous community access and authorized administrators. `Admin/SessionController` uses Laravel's existing web session guard, an explicit `is_admin = true` credential constraint, generic credential errors, session regeneration on login and session/token invalidation on logout. There is no registration, password-reset or community-account UI. `AdministratorPasswordLength` enforces bcrypt's 72-byte limit at setup/login; the setup command also requires 12 characters with mixed case, number, symbol and confirmation. No remember-login option is enabled.

`AppServiceProvider` defines the `access-admin` gate, a five-attempt/minute/IP login limiter and a 30-attempt/minute/administrator review limiter. Every dashboard/list/detail/photo/status/logout route has authentication and administrator authorization. Form Requests repeat authorization on filtered/review operations. `AdminPrivacy` adds no-store/private, same-origin referrer, noindex and nosniff headers to admin responses, including image streams. CSRF/origin middleware remains active. The role is read from the user record on each new authenticated request.

`Admin/DashboardController` groups database counts by status; unknown legacy states contribute only to the total. `Admin/ReportController` validates search/lake/type/status/date/page filters, uses bound queries and eager relationships, and paginates 15 reports at a time. Dates are displayed in the configured application timezone (currently UTC). Search covers descriptions/lake names, not reporter contacts. All details and notes use escaped Blade output. Incident coordinates are displayed as unverified reporter-supplied values without sending private points to an external map service.

Photos use a protected report-ID URL, an allowlisted relative filename and content MIME, then stream from the private disk under a generic evidence filename. Responses do not disclose stored paths; no permanent public storage URL is created. Missing/unsafe paths or unexpected content return 404.

`Admin/ReportStatusController` validates the requested and expected status, locks the current report inside a transaction, rejects stale pages/invalid transitions, and inserts an audit entry before committing. Allowed transitions are pending to verified/rejected, and verified to resolved; rejected/resolved are terminal. Audit administrator, previous/new states and timestamp are server-assigned. Optional notes are limited to 2,000 characters. Audit persistence failure rolls back the status change and returns a generic error without logging SQL/request contents. No audit edit/delete endpoint or report deletion feature exists.

`admin:create` is an explicit interactive command with hidden password entry and visible-input fallback disabled. It verifies configured/connected `aquamap_laguna`, accepts only a new email identity, and hashes the chosen password through the existing model cast. It refuses unattended use and existing accounts, and never promotes them. The only command database exception is isolated testing SQLite `:memory:`. No real account was created during development; the owner must run the command locally. No dependencies or credentials changed.

The forward migrations preserve existing rows and default every existing user to non-administrator. Audit parent restrictions protect history from accidental cascaded deletion; future retention/anonymization must account for them. [Prototype retention policy](../../docs/RETENTION_POLICY.md) defines manual review periods, minimization, copies/backups and owner authorization. Nothing automatically deletes reports or evidence. Migration rollback would discard role/audit data; prefer reviewed forward fixes.

## Public map flow and browser boundary (Observed)

`MapController@index` reads supported categories with explorer metadata, plus the three legacy San Pablo profiles. It selects explicit attributes, eager-loads the existing fish relationship, and uses constrained `withCount` to count only reports currently in `verified` status. No report models/contents/contacts/points/photos/audits are loaded or serialized. This requested aggregate is the only exception to individual report privacy; resolved, rejected and pending records are excluded. See `docs/RETENTION_POLICY.md`.

The allowlisted lake JSON contains the original eight attributes plus category, aliases, site/spring type, official URL, sanitized geography and verified_report_count. `ExplorerProfile` checks HTTP(S) URLs (without credentials), WGS84/source-checked metadata/date, bounded numeric coordinates, closed polygon rings and supported GeoJSON shapes. Invalid/unverified geometry becomes null; there is no fallback to unconfirmed legacy points. Source references are projected to four public fields. Images require a confined existing local asset and complete source/permission/author/alt metadata; private paths and external images are excluded.

Blade escapes profiles/references and embeds JSON with `Js::encode`. JavaScript clones escaped profile DOM, removes duplicate IDs, creates compact textContent popups, and renders Leaflet polygons/river lines alongside keyboard-accessible selection markers. Shapes also support keyboard selection. Search matches names/aliases/locality, dynamic counts reflect the search, categories hide both sidebar entries and map layers, and reset clears filters/selection and fits source-derived bounds. Empty/missing geometry never invents a center. Mobile filters precede the map with a jump link. OSM tile attribution and offline/error notices remain; CSS keeps the existing Tailwind v4 environmental theme.

The additive migration stores category/site/spring type, official URL and four nullable JSON fields (aliases/geography/research_references/image). Existing columns and IDs remain unchanged. `ExplorerSeeder` validates the configured/connected target database, permits only in-memory test exceptions, runs serially in a transaction and reads trusted `database/data/explorer.json`. Case/alias ambiguities and metadata conflicts abort. Existing original attributes are never overwritten; missing metadata is supplemented. Repeated imports preserve values and timestamps, including MySQL JSON key ordering. Root seeders remain unchanged and the import is explicit.

Current catalogue: five lake profiles, two selected river reaches, three waterfalls and one resort point. Four lake polygons and two MultiLineStrings use inspected OSM objects; Pandin is a sourced shoreline node. Al Fresco uses owner-published GeoCoordinates and is explicitly a resort, not a spring source. All existing scientific data remains unchanged. Original journal datum/precision, survey accuracy, complete river coverage, additional locations/resorts and photo assets remain unresolved. The recorded permitted Bunot photo could not be transferred; current live profiles all show placeholders. Exact claims/versions/licenses/backlog are in `docs/RESEARCH_SOURCES.md`.
## Fish evidence flow (Observed)

The controller eagerly loads each included water body's `fishSpecies` in one additional query. It builds a separate `fishByLake` view array with six species fields (`id`, common/scientific names, water type, habitat requirements and source URL), plus occurrence URL, evidence type, sampling period, publication year and public compatibility status. No raw model relationships, private assessment explanation, or timestamps are rendered. Both reference URLs use the same HTTP(S) allowlist as lake sources.

`resources/views/map/fish-cards.blade.php` escapes these fields and distinguishes documented occurrence, general species habitat and potential compatibility. Evidence requires a recognized type plus a source, sampling period and publication year; incomplete legacy records are labeled incomplete. Missing associations do not imply absence. Cards are rendered in the non-JavaScript reference section and cloned from that escaped DOM into the selected-lake panel. The separate fish projection remains unchanged while the public lake JSON contract now explicitly adds explorer metadata and aggregates.

Current data is one Nile tilapia profile with three historical aquaculture links: July-September 2017 sampling, article year 2019. FAO general biology has its own species source, separate from the lake-specific study. All seeded links and all Day 3 public compatibility displays remain `insufficient_data`: there are no validated current lake measurements or assessment engine. Wild occurrence is supported as an evidence label, but no wild records were seeded.

Decision: reuse the unique lake/species pair for one representative occurrence study, with nullable type/month-level period/year rather than inventing exact collection days or adding a study-history subsystem. Multiple studies per pair remain a future design requirement. Primary research claims, access limitations and missing evidence are in `docs/RESEARCH_SOURCES.md`.

## Seeding and safety boundary (Observed)

`DatabaseSeeder` calls `WaterBodySeeder` followed by `FishSpeciesSeeder`; neither creates test users. Each seeder checks resolved connection configuration before connecting: MySQL database name must be exactly `aquamap_laguna`, then `SELECT DATABASE()` is checked on the write connection before writes. The only exception is SQLite `:memory:` while testing. Seeder reads use the verified write connection.

Lake seeding upserts three geographic metadata records in one transaction using `(name, municipality)` as identity. Fish seeding has a separate transaction, requires exactly one existing record per target lake, refuses ambiguous duplicate scientific names, and reuses the species by scientific name and links by their unique pair. It updates the seeded profile/evidence/status fields but leaves unrelated species and lake attributes alone. Day 3 live seeding ran only `FishSpeciesSeeder`, preserving lake IDs/timestamps and every attribute.

Repeat serial runs retain IDs and timestamps when values are unchanged. Neither lake identity nor species scientific name has a database unique constraint; run seeders serially. The existing pair constraint prevents duplicate links. No destructive migrations or resets were run. Reversing the new migration would drop study metadata, so routine rollback is not a data-safe recovery strategy; prefer reviewed forward fixes.

The locality field is a label, not a jurisdiction polygon. Yambo's description records San Pablo City, Rizal, and Nagcarlan. Published geographic points have an unconfirmed datum/accuracy and are not surveyed centroids. See `docs/RESEARCH_SOURCES.md`.
